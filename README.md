# تعديل موقع تَبصَّر — الملفات الجاهزة

## تشغيل إيميلات التسجيل والتحقق منها

- ضع `ZEPTOMAIL_TOKEN` في `.env` مع `EMAIL_FROM_ADDRESS` و`EMAIL_FROM_NAME` و`PUBLIC_SITE_URL`، وفق `.env.example`. المفتاح خاص بالسيرفر ولا يحمل بادئة `VITE_`.
- دالة الإيميل تتحقق من التسجيل في قاعدة البيانات قبل الإرسال، فتحتاج كمان `SUPABASE_SERVICE_ROLE_KEY` (سري، على السيرفر فقط) وتشغيل `supabase/security.sql`. تفاصيل الحماية كاملة في `SECURITY.md`.
- أعد تشغيل `npm run dev` بعد تعديل إعدادات السيرفر. التشغيل المحلي و`npm run preview` يربطان `/api/send-registration-email` بنفس المعالج الموجود في `api/send-registration-email.js` عبر `server/registration-email-plugin.js`.
- عند النشر على Vercel، انشر المشروع كاملًا مع مجلد `api` واضبط المتغيرات في إعدادات المشروع. رفع `dist` وحده إلى استضافة ملفات ثابتة لا يشغّل البريد؛ يلزم سيرفر يشغّل مسار API.
- نفّذ `npm test` و`npm run build` قبل النشر. الاختبارات تستخدم مزوّد بريد وهميًا ولا ترسل رسائل فعلية، وتغطي الربط في التطوير والمعاينة، وأخطاء الإعدادات والمزوّد والاتصال والاستجابات غير الصالحة.
- بعد النشر، تحقّق من إرسال طلب تجريبي إلى بريد تملكه ومن وصوله. قبول مزوّد البريد للرسالة لا يثبت وصولها إلى الوارد؛ راجع سجل التسليم في ZeptoMail إذا لم تصل.
- واجهة النجاح تعرض حالة رسالة التأكيد وتسمح بإعادة محاولة البريد وحده عند الفشل. لا تُكرر الطلب تلقائيًا عند انقطاع الاتصال، لأن المزوّد قد يكون قبله بالفعل. لا يُرسل بريد للتسجيل المحاكى بدون Supabase.

مراجع التنفيذ: [ربط مسارات السيرفر في Vite](https://vite.dev/guide/api-plugin#configureserver)، [استجابة قبول الرسالة في ZeptoMail](https://www.zoho.com/zeptomail/help/api/email-sending.html).

انسخ هذه الملفات فوق الملفات الموجودة في المستودع بنفس المسارات:

```
patch/src/index.css              →  src/index.css
patch/src/pages/Home.jsx         →  src/pages/Home.jsx
patch/src/pages/Home.module.css  →  src/pages/Home.module.css
patch/public/assets/*.png        →  public/assets/   (5 صور جديدة)
```

## وش تغيّر

**١. الألوان (`src/index.css`)** — استبدلت التوكنز الزيتونية/البنية بألوان هوية تَبصَّر:
- `--green-500: #0ABD70` هو اللون القائد (٦٠٪)
- `--gold-*` صار التركوازي `#027286` (كان ذهبي — نفس اسم المتغير حتى لا تتأثر صفحات التسجيل والأدمن)
- `--coral-500: #D06858` و `--mauve-500: #9078A8` لمسات فقط (٣٠٪ / ١٠٪)
- `--ink-*` صار تركوازي داكن `#02313A` بدل البني
- `.btn-primary` صار أخضر البراند بدل الذهبي
- شريط النِسب صار ٦٠/٣٠/١٠
- أُلغيت خامة الورق (`body::after`) وخفّفت نمط النجوم في قسم الشركاء

**٢. سكشن «عن المعسكر» (`About` في `Home.jsx`)** — استُبدلت الكرة ثلاثية الأبعاد ببانر صورة كامل مع تدرّج تركوازي داكن والنص على اليمين، وتحته شريط ٤ إحصائيات بخطوط رفيعة. تم حذف `import AboutGlobe`.

**٣. سكشن «مسارات التحدّي» (`Pillars`)** — صار كاروسيل أفقي: العنوان ثابت على اليمين، والكروت تتحرك بأسهم يمين/يسار + سحب بالماوس + scroll-snap. كل مسار صار بصورة بدل الأيقونة، وحُذفت التاقات الإنجليزية.

**٤. سكشن «الشركاء»** — خلفية تركوازية داكنة `#02313A` مع إضاءة خفيفة، وكروت شفافة `rgba(255,255,255,.05)` بلوحات شعار بيضاء. الكلاسات العامة `.partner-tag` / `.partner-mark` / `.partner-en` / `.partner-foot` في `index.css` ما صار لها استخدام (استُبدلت بكلاسات داخل `Home.module.css`) — تركتها كما هي حتى لا تتأثر أي صفحة ثانية.

**٥. سكشن «الرعاة»** — صار شريطًا يدور تلقائيًا (marquee) بلا أسهم: كل كرت = لوقو الجهة + اسمها، دوران متصل ٣٨ ثانية، يتوقف عند مرور الماوس، وحوافه متلاشية. أضف الرعاة من مصفوفة `sponsors` في أعلى دالة `Sponsors`:

```js
const sponsors = [
  { name: 'اسم الجهة', logo: '/assets/logo.png' },
  { name: 'شعار الجهة', logo: null },   // null = مكان شعار بديل
  { name: 'كيوبكس', logo: '/assets/cubex-logo.png', dark: true },  // dark = خلفية سوداء للشعار
]
```
القائمة تُكرَّر مرتين تلقائيًا حتى يكون الدوران متصلًا — لا تكررها يدويًا.
